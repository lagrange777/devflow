# Полный цикл разработки на самом Devflow

Реальная задача: улучшить собственную команду `doctor`, чтобы перед платным AI-запросом она проверяла наличие Git, Docker CLI и доступность Docker daemon. Это помогает обнаружить проблему окружения до запуска разработки и расхода API-баланса.

19 октября 2026 года задача проведена через настоящий API из `codex-chat-cli/.env`, Git-репозиторий, GitHub PR, CI и GitHub Release.

## Проверяемый результат

- [PR #2 — Check Git and Docker before doctor calls AI](https://github.com/lagrange777/devflow/pull/2): сгенерированный код и 10 тесткейсов, связанных с реально выполненными Go-тестами.
- [GitHub CI основной ветки](https://github.com/lagrange777/devflow/actions/runs/39226888249): форматирование, анализ, тесты и сборка прошли.
- [GitHub Release v0.1.0](https://github.com/lagrange777/devflow/releases/tag/v0.1.0): исполняемый файл macOS ARM64, manifest и SHA-256.
- [Артефакты AI-процесса](https://github.com/lagrange777/devflow/releases/download/v0.1.0/development-evidence.json): требования, сценарии, спецификация, результаты этапов, расход токенов, ревью и проверки готового бинарника.

Все семь этапов прошли последовательно. В успешном запуске сохранены 9 успешных ответов модели: этап реализации потребовал двух доработок. Сначала тест обнаружил недостаточную защиту ошибок от утечки подставного секрета, затем анализатор обнаружил ошибку импортов в тестах. Код не переходил дальше до прохождения проверок. AI-ревью итогового коммита не обнаружило блокирующих замечаний.

Проверенный SHA: `385eaacce195dd3641812c213782fd6692d346e4`. После успешного CI и AI-ревью оператор слил PR и явно одобрил этот SHA для команды `devflow release`. Сам Devflow повторно проверил merged PR, обязательные GitHub checks, тесты и сборку, создал тег и опубликовал релиз.

## Как участвовал AI

1. Превратил задачу в четыре критерия приёмки.
2. Подготовил десять позитивных, негативных и граничных тесткейсов.
3. Написал техническую спецификацию и согласованный список файлов.
4. Сгенерировал Go-код и тесты, затем исправлял ошибки по настоящим журналам команд.
5. Подготовил описание PR; существующий draft был найден и обновлён по имени ветки.
6. Отдельным запросом проверил diff относительно требований и спецификации.
7. Подготовил release notes для проверенного коммита.

Оркестратор на Go проверял порядок, контрольные суммы артефактов, допустимые пути, фактическое выполнение тестов и соответствие SHA. Скиллы задавали инструкции этапов; программные инварианты определяли возможность перехода.

## Проверка готового бинарника

Бинарник распакован из релизного архива и успешно выполнил `doctor` в режимах `docker` и `local` с настоящим AI API. Отдельно, без ключа, проверены неверный runner, отсутствие Git и настоящий таймаут процесса примерно через пять секунд. Ошибки возникли до чтения отсутствующего файла конфигурации AI.

```bash
./bin/devflow doctor --env-file ../codex-chat-cli/.env
./bin/devflow doctor --runner local --env-file ../codex-chat-cli/.env
```

## Что потребовало вмешательства оператора

Первые попытки выявили проблему оркестратора: AI получал имя неотформатированного файла и повторял тот же текст. Исправление автоматического форматирования Go прошло отдельный [PR #1](https://github.com/lagrange777/devflow/pull/1). Истории неудачных попыток приложены к релизу.

На этапе PR закончился API-баланс (`credit_balance_exhausted`). Оператор создал draft из уже проверенного коммита. После пополнения баланса тот же запуск продолжился, обновил draft и завершил AI-ревью и release notes. Остановка не требовала повторной генерации кода. Ключ не копировался и не публиковался.

# Первый запуск на учебном HTTP-сервисе

19 октября 2026 года выполнен сквозной запуск с настоящим API из `codex-chat-cli/.env`. Ключ не копировался. Модель: `gpt-5.3-codex`.

## Задача

Добавить в существующий Go HTTP-сервис параметр `name` для `/hello`, сохранить ответ без параметра, ограничить имя 40 Unicode code points и вернуть HTTP 400 при превышении лимита.

## Результат

Все семь этапов прошли последовательно. AI создал 5 критериев приёмки и 11 тесткейсов, техническую спецификацию, код и тесты, описание PR, независимое ревью и release notes. Блокирующих замечаний в этом запуске не было; цикл доработок отдельно проверен сквозными тестами с ошибкой форматирования и замечанием ревью.

- Запуск: `runs/live-demo/run.json`, статус `released`.
- Проверенный коммит: `a9a770a122770933746e7056f85b763ce75a6a65`.
- Локальная версия: `v0.1.0-demo`.
- Архив: `runs/live-demo/dist/app-v0.1.0-demo-darwin-arm64.tar.gz`.
- API-вызовов: 7; входных токенов: 52 083; выходных: 7 381.
- Пройдены настоящие `gofmt`, `go vet`, `go test -json -count=1` и `go build`.
- Исходная рабочая копия учебного репозитория сохранена на ветке `main`; изменения находятся в отдельной ветке и worktree.

Архив распакован, исполняемый файл запущен. Проверены HTTP-запросы:

| Запрос | Результат |
|---|---|
| `/hello` | 200, `Hello, world!` |
| `/hello?name=Go` | 200, `Hello, Go!` |
| имя из 40 кириллических символов | 200, полное имя в ответе |
| имя из 41 кириллического символа | 400 |

Отчёт: `runs/live-demo/http-smoke.json`. В этом первом запуске приложение использует порт 8080; проверка выполнена через `http://[::1]:8080`, поскольку IPv4-порт уже занимал Docker исходного проекта. Для новых учебных репозиториев пример в `examples/hello` использует порт 18080.

## Дополнительная проверка

`go test ./...` и `go vet ./...` прошли. Отдельно выполнен `DEVFLOW_TEST_DOCKER=1 go test ./internal/flow -run TestDockerChecks -v`: стандартный Docker-runner прошёл форматирование, анализ, тесты и сборку с отключённой сетью, ограничениями ресурсов и без API-ключей в контейнере.

GitHub-публикация в демонстрации выключена. Создание PR, push и GitHub Release реализованы через `gh` и включаются флагом `--publish`; инварианты merged PR, совпадения head SHA и обязательных checks проверены локальными тестами. Настоящая публикация в пользовательский репозиторий не выполнялась. Деплой приложения на сервер в MVP не входит.
